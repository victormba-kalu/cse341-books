6.a. Include a GitHub link to a file that shows one other implementation decision you made.

GitHub link: https://github.com/victormba-kalu/cse341-books/blob/main/src/controllers/books.js

6.b. What decision does this file show, and why did you make that choice?

Answer: The file shows how tasks seperation and safe error handling.
Instead of putting everything together like the route urls, db queries, I keep them seperated.
The controller's job is to take the web request, ask the model for the book data and send back a clean
JSON response. This keeps my code clean and easy to read.

As well, to ensure good error handling, if a book is found, it sends a clear 200 status.
If it isn't found, it sends a 404 error.
If the database crashes, the catch block catches it, and logs the error to my terminal so I can fix it.
It also sends a 500 internal server error to the user.

I made this choice because it protects my app. If something breaks, users and potential hackers only see a friendly error message 
instead of private database details or sensitive crash reports.
